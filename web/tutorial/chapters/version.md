# 第 12 章 · 版本说明与最佳实践

本章说明本教程自身的版本机制，并汇总使用 TestGen（知识管理系统）的最佳实践与常见坑。

## 12.1 教程版本机制

教程随系统**版本化**管理，规则如下：

- **大版本随系统**：教程大版本号 = 前端 `package.json` 的 `major`。当前前端为 `2.0.0`，故教程大版本为 `2`；
- **小版本独立**：教程小版本（`minor`）独立于系统，仅当教程**内容**更新时递增（如补充章节、修正截图、更新表述），系统版本不变；
- **版本显示**：教程页标题与每章底部均显示 `教程 vX.Y · 系统 vA.B.C · 更新于 <日期>`；
- **系统升级跟随**：当系统升到 `2.x` 时，教程大版本自动跟随为 `2` 并重置 `minor` 为 `0`；届时需逐章检查内容是否仍准确。

本教程当前版本：**教程 v2.6 · 系统 v2.0.0**。

## 12.3 最佳实践

1. **先传代码再生成**：新项目范围为空是正常的，先上传代码 / PRD 让图谱与功能模块生成，再生成用例。
2. **善用知识上下文**：生成前点「刷新上下文」，确认历史用例 / 脚本 / 图谱节点数量，生成结果会继承既有经验。
3. **编辑即沉淀规则**：在草稿审阅中每次修改并保存，都会自动总结质量规则，长期提升生成质量。
4. **冲突走 merge**：批量入库遇冲突优先 `merge`，保留双方知识；质量门控不达标就补结构（标题 / 列表 / 代码块）后重提。
5. **闭环回流**：执行失败用回测页「草稿审核」去向生成缺陷草稿，回归报告用「沉淀入库」存档并生成重测计划，形成 生成 → 执行 → 回流 → 再生成 的正向循环。
6. **检索优先混合语义**：自然语言意图用「混合语义」，精确术语用「关键词」；语义无命中会自动回退，无需手动重试。
7. **知识库版本化**：重要里程碑建议用「Git 协同」提交并推送到远端，变更可追溯、可回滚；push 前先 pull 对齐，冲突优先「保留双方」。

## 12.4 常见坑

- **范围为空**：不是 bug，是新项目未上传材料；上传后即出现真实模块。
- **生成结果过短**：AI 偶发短响应被质量门控拒收，重试或调大 `maxTurns`。
- **中文文件名乱码**：BFF 已做 UTF-8 加固与文件名还原，正常上传不会乱码；若仍乱码多为源文件本身编码异常。
- **AI 平台不可达**：先点「测试连接」看双系统结果，再核对供应商 / key / endpoint。
- **重测计划显示 Mock**：说明 KS 当前不可达，页面用契约一致的兜底数据展示流程；恢复 KS 后刷新即可读取真实数据。
- **Git 推送被拒**：多为远端有他人提交，先 pull / fetch 合并（可能触发冲突处理）后再 push。

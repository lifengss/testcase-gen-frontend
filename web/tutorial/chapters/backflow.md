# 第 6 章 · 执行回流：从失败到知识

测试执行发现的失败，不应只停留在 CI 报告里。执行回流把失败用例**结构化**为缺陷草稿，沉淀为可复用的缺陷经验。

![执行回流](/tutorial/assets/backflow.png "执行回流：上传执行报告 → 解析失败 → 缺陷草稿")

## 6.1 上传执行报告

在执行回流视图，通过 **上传执行报告** 卡片选择报告文件，支持：

- **JUnit / pytest XML**：标准测试框架输出；
- **JSON 摘要**：自定义结构的失败摘要。

## 6.2 解析失败 → 缺陷草稿（exec_backflow）

上传后系统解析其中的失败用例，自动生成 **结构化缺陷草稿**（来源标记 `exec_backflow`）：

- 抽取失败用例名、断言信息、异常堆栈要点；
- 关联当前项目的知识上下文（如相关模块、历史缺陷）；
- 写入当前项目草稿箱，进入「草稿审阅 / 入库看板」流程。

这样，一次线上或回归失败，会反哺为质量资产，下次生成同类模块用例时优先覆盖该缺陷点。

## 案例：上传一份失败报告，生成缺陷草稿

1. 在 CI 拿到 `pytest` 失败报告 `report.xml`，在执行回流页上传。
2. 系统解析出 3 条失败用例（如 `test_login_timeout`、`test_order_race`）。
3. 生成 3 条 `exec_backflow` 缺陷草稿，进入草稿箱。
4. 到草稿审阅查看，确认后入库看板批量确认，沉淀为 `defect-experience` 知识。
5. 后续在生成中心为相关模块生成用例时，知识上下文会命中这些缺陷经验，自动加强对应分支覆盖。

> 提示：执行回流与生成是「知识闭环」的另一半——生成 → 执行 → 失败 → 回流 → 再生成，形成正向循环。

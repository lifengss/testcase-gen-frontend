# 第 5 章 · 入库看板：知识沉淀与冲突处理

入库看板是知识从「草稿」正式成为「团队共享资产」的关口。它提供 **双通路入库**，并内置 **冲突检测** 与 **质量门控**。

![入库看板](/tutorial/assets/commit.png "入库看板：批量确认入库 + 草稿列表")

## 5.1 双通路入库

- **批量确认入库**（页头 **⬡ 批量确认入库** 按钮）：一次性对多条草稿做冲突检测 + 质量门控后入库，适合成批沉淀；
- **单条确认**：在草稿条目上单独确认，适合精细控制。

两者都走 KS 的入库链路，并写审计日志。

## 5.2 冲突检测与解决

当新草稿与库中已有内容发生模块 / 页面冲突时，系统会在入库前拦截并提供决议：

- **merge**：合并双方内容；
- **overwrite**：以新草稿覆盖旧内容；
- **keep_both**：保留双方（新草稿入库，旧内容本就在库）。

> 说明：冲突处理后草稿状态会从 `conflict` 正确回写为 `pending` 再入库，不再出现「冲突草稿悬挂」问题。

## 5.3 质量门控

入库前系统对内容做质量评分（总分 ≥ 60 才允许入库）。规范结构包括：

- 含 Markdown **标题**；
- 含 **列表**；
- 含 **代码块** 等结构化元素。

内容过短或来源可信度低会被拒收，提示你补充规范结构后重提。

## 案例：批量确认并解决一次模块冲突

1. 在生成中心生成一批 `auth` 模块用例并保存到草稿。
2. 打开入库看板，点击 **⬡ 批量确认入库**。
3. 系统检测到 `auth` 某页面与库中既有内容冲突，弹出决议选项，选择 **merge**。
4. 冲突解决后草稿经质量门控（结构达标）正式入库，状态变为 `merged`。
5. 到「项目空间」概览，已入库知识页数增加；审计日志记录了本次 commit。

> 提示：若某条被质量门控拒收，它不会悬挂，而是回退为 `pending`，可在页面修改结构后重提。

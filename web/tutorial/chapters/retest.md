# 第 7 章 · 回测：测试报告存档与复盘

回测关注「历史测试报告」的沉淀与回溯。上传的测试报告不再只是一次性产物，而会成为可供团队复盘的知识文档。

![回测](/tutorial/assets/retest.png "回测：上传测试报告 → 沉淀为 test-reports 知识")

## 7.1 上传测试报告

在回测视图，通过上传卡片选择报告文件，支持：

- **Markdown（.md）/ 文本（.txt）**：人工整理的回归报告；
- **JSON（.json）**：工具导出的结构化报告。

## 7.2 沉淀为 test-reports 知识

上传后，报告会沉淀为知识库的 **`test-reports`** 文档，并在回测列表（`retestList`）中列出：

- 可随时打开历史报告，对比不同轮次的覆盖范围与结论；
- 与生成、回流共享同一知识体系，便于在「生成 / 审阅」时引用过往结论。

## 案例：存档一轮回归报告供后续回测

1. 完成一轮全量回归，把汇总报告 `regression-2026Q3.md` 在回测页上传。
2. 系统将其存入当前项目知识库 `test-reports`，回测列表新增一条记录。
3. 下个迭代开始前，打开该报告，确认上次发现的 5 个风险点是否已被用例覆盖。
4. 若发现覆盖缺口，回到生成中心针对缺口模块补生成用例，闭环补齐。

> 提示：回测与执行回流的区别——回测偏向「整轮报告的存档复盘」，执行回流偏向「失败用例的结构化缺陷提取」。

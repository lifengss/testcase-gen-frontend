# 第 6 章 · 回测 · 报告回流：沉淀、审核与重测计划

回测页是测试 / 执行报告的统一回流入口（原「执行回流」已并入本页）：测试执行产生的失败，不应只停留在 CI 报告里，而要反哺为可复用的缺陷经验。上传报告后有两种去向可选——界面上对应两个分段按钮：**「回测回流 · 沉淀入库」**（解析拆分后直接写库）与 **「执行回流 · 草稿审核」**（整篇原文生成缺陷草稿，人工确认后入库）。

![回测](/tutorial/assets/retest.png "回测：上传测试/执行报告 → 沉淀入库或草稿审核 → 重测计划")

## 6.1 上传报告与去向切换

在回测视图，通过 **上传测试 / 执行报告** 卡片选择报告文件，支持：

- **Markdown / 文本（.md / .txt）**：人工整理的回归报告；
- **JSON（.json）**：工具导出的结构化报告；
- **JUnit / pytest XML（.xml）**：标准测试框架输出。

上传卡片下方的 **去向切换** 决定报告的处理方式：

| 去向 | 处理 | 落点 |
|---|---|---|
| 沉淀入库 | KS 真解析：抽取记录 → 归一化 → 按状态 / 严重度分流 | 直接写入知识库 `defect-experience`（失败 / 缺陷）与 `test-cases`（通过），可供重测计划使用 |
| 草稿审核 | 不解析，整篇原文归档 | 生成 1 条 `exec_backflow` 缺陷草稿，进草稿箱人工确认后入库 |

## 6.2 沉淀入库（默认）

选「沉淀入库」上传后，KS 端会做三步处理：

1. **抽取**（`extractTestReportRecords`）：从报告中抽出记录数组（兼容 Markdown 表格、JSON `cases/results/tests` 等结构）；
2. **归一化**（`normalizeTestReportRecord`）：pytest 的 `nodeid/outcome` 等原始字段转为统一的标题、状态、证据；
3. **分流**（`classifyTestReportRecord`）：失败 / 缺陷 / 严重度高 → `defect-experience`；通过 / 低严重度 → `test-cases`，带 `status / severity / uploadedAt` 元信息落盘。

入库后可随时在下方「沉淀报告列表」打开历史报告，对比不同轮次的覆盖范围与结论。

## 6.3 草稿审核（原执行回流）

选「草稿审核」上传后，整篇报告原文生成 **1 条** `exec_backflow` 缺陷草稿（不做拆解，保留完整现场），出现在本页「待审核回流草稿」区，同时进入「入库看板」的草稿缓冲层：

- 可打开草稿查看全文、编辑、删除；
- 确认无误后单条入库或随看板批量入库，沉淀为 `defect-experience` 知识；
- 入库后的草稿才参与重测计划排序。

## 6.4 重测计划：谁该被优先回归

「重测计划」基于已沉淀的 **缺陷经验**（`defect-experience`）自动产出下一轮回归的候选清单。点击 **生成重测计划**，系统按 **优先级** 降序排出候选：

- **优先级公式**：`priority = 0.4 × 状态分 + 0.6 × 近期失败 + 0.4 × 严重度`
  - 状态分：失败 / 错误最高，通过最低；
  - 近期失败：按失败距今时间分档（7 天 / 30 天 / 90 天内更高，越近越高）；
  - 严重度：`critical > high > medium > low`。
- 每条候选展示：标题、严重度色标、最近状态、所属分组、**优先级进度条**与具体加权分；
- **范围筛选**（面板顶部切换）：
  - **全量**：所有缺陷经验条目；
  - **仅失败**：只看最近状态为失败 / 错误的条目（失败置顶）；
  - **高严重度**：只看 `critical` / `high` 严重度条目。

> 说明：重测计划为**建议排序**，不直接修改任何用例或知识；数据来自 KS 真实端点（`POST /api/retest/plan`），若 KS 不可达则由 BFF 以契约一致的 Mock 数据兜底并在页面上标注「Mock」。

## 案例：上传失败报告 → 缺陷草稿 → 沉淀 → 生成重测计划

1. 在 CI 拿到 `pytest` 失败报告 `report.xml`，在回测页上传，去向选 **草稿审核**。
2. 页面生成 1 条 `exec_backflow` 缺陷草稿，出现在「待审核回流草稿」区。
3. 到入库看板批量确认，草稿沉淀为 `defect-experience` 知识。
4. 再上传整轮回归汇总 `regression-2026Q3.md`，去向选 **沉淀入库**，失败条目直接分流入库，列表可见。
5. 面板范围选 **全量**，点击 **生成重测计划**，看到按优先级降序的候选清单与进度条；切 **仅失败** 定位最需补回归的模块。
6. 回到生成中心，针对缺口模块补生成用例，闭环补齐。

> 提示：生成 → 执行 → 失败 → 回流 → 再生成，形成「知识闭环」；回流与回测已统一入口，区别只在你选「草稿审核」还是「沉淀入库」。

# 第 11 章 · 业务流程使用案例

前面各章按功能模块介绍了每个页面怎么用。本章按**真实业务场景**串联一遍完整操作流程：遇到"从零建库""版本回归""缺陷复盘""知识沉淀与共享"这类场景时，应该如何一步步操作 KS。

> 约定：以下步骤中的「生成中心」「草稿审阅」「入库看板」等均指左侧导航对应模块；涉及上传时，文档材料、代码材料均位于「生成中心」页的对应上传卡片。

## 11.1 场景一：新项目从零到一，建立第一个知识闭环

**业务背景**：接手一个全新模块（如「订单管理」），当前没有任何测试用例、缺陷经验，需要从零搭建该项目的测试知识库。

**操作步骤**：

1. **建库**：进入「项目空间」，新建项目「订单管理」；侧栏底部「当前项目」切换到该项目。
2. **上传材料**：在「生成中心」的文档材料区上传 PRD / 需求文档（支持 `.md` / `.docx`），代码材料区上传代码压缩包（`.zip` / `.tar` / `.7z`）。上传后自动生成项目 Wiki 页面与 API 调用依赖图谱。
3. **刷新上下文**：点「刷新上下文」，确认知识上下文中已出现刚生成的 Wiki 页面、功能模块与图谱节点数。
4. **生成用例**：选择「按功能模块」测试范围，勾选订单相关模块，点「生成测试用例」，等待流式输出。
5. **审阅与入库**：切到「草稿审阅」，检查生成结果，必要的修改后点「入库」；再切到「入库看板」批量确认，完成知识沉淀。

**预期结果**：项目知识库中出现首批测试用例与项目 Wiki；下次再为该项目生成用例时，知识上下文会带上这批沉淀，质量持续提升。

## 11.2 场景二：版本回归，执行报告回流并规划重测

**业务背景**：订单模块迭代到 V2，执行完回归测试拿到一份执行报告（`.json` / `.xml` / `.md` / `.txt`），部分用例失败，需要沉淀失败原因并规划重测。

**操作步骤**：

1. **上传报告**：进入「回测 · 报告回流」，上传执行报告。
2. **选择去向**：
   - 失败 / 缺陷类记录 → 选「沉淀入库」，KS 自动解析拆分为 `defect-experience`（缺陷经验）页面；
   - 需要人工确认 → 选「草稿审核」，整篇报告生成 1 条 `exec_backflow` 草稿，到「草稿审阅」人工确认后入库。
3. **生成重测计划**：报告入库后，回测页自动按优先级公式生成一轮**重测计划**，按影响度排序待重测项。
4. **再生成**：回到「生成中心」，知识上下文已包含本轮缺陷经验，可针对重测计划中的模块补生成用例。

**预期结果**：执行报告自动沉淀为缺陷经验知识；重测计划明确下一轮要测什么；缺陷经验在后续生成 / 检索中复用。

## 11.3 场景三：缺陷复盘，检索历史经验并定位影响面

**业务背景**：线上反馈"用户密码错误多次导致账号锁定"，需要复盘是否历史上有过同类问题，以及该逻辑会影响哪些业务步骤。

**操作步骤**：

1. **检索**：进入「知识检索」，模式切到**混合语义**，输入"用户登录密码错误多次导致锁定"。
2. **看结果**：语义命中项会标注「语义命中」徽标，直接展示历史缺陷经验与质量规则；无命中时系统自动回退关键词模式。
3. **定位影响面**：进入「知识图谱」，切到**业务流依赖**，找到登录 / 鉴权相关模块，查看其上下游节点，评估影响范围。

**预期结果**：用一句话找到历史同类缺陷；图谱直观展示受影响业务步骤，支撑影响面评估。

## 11.4 场景四：知识沉淀与团队共享，走 Git 版本化

**业务背景**：知识库沉淀到一定规模，需要提交到远端仓库，实现团队共享与变更可追溯；期间与他人协作还可能遇到冲突。

**操作步骤**：

1. **配置远端**：进入「Git 配置」，填写远端地址、默认分支 `main`、提交身份（用户名 + 邮箱），点「保存配置」并「初始化仓库」。
2. **提交**：切到「Git 状态」，查看未跟踪 / 已修改文件，填写提交说明（如 `feat: 沉淀订单模块用例`），点「提交」。
3. **同步**：点「推送」到远端；再次开发前先「拉取 / 抓取」对齐远端。
4. **处理冲突**：若与他人同时修改同名知识页面产生冲突，「Git 状态」显示冲突文件数，前往「Git 冲突处理」按需选择保留本地 / 保留远端 / 保留双方，或手动编辑后刷新。

**预期结果**：知识库进入 Git 版本管理，变更可追溯、可回滚、可团队共享；冲突在页面内可视化解决，不丢失团队知识。

## 11.5 场景五：多项目并行，切换项目隔离上下文

**业务背景**：同时维护订单系统、会员系统等多个项目，各项目知识相互独立，需要随时切换上下文，避免串数据。

**操作步骤**：

1. **建立多个项目**：在「项目空间」分别新建「订单管理」「会员系统」等独立项目。
2. **切换上下文**：侧栏底部「当前项目」下拉切换当前项目（或顶部项目选择），各页面的草稿、知识库、图谱、检索均按当前项目隔离。
3. **核对归属**：上传 / 生成 / 入库时注意标题旁的项目标签，确认数据落在预期项目下。

**预期结果**：多项目并行互不干扰，切换即切换整套上下文，跨项目不串数据。

> 提示：以上五个场景覆盖了知识管理的典型闭环（建库 → 沉淀 → 复盘 → 共享 → 并行）。实际使用时，可按本系统「知识闭环」链路把各场景串联起来：**上传材料 → 生成 → 审阅 → 入库 → 执行回流 → 再生成**，让每一次测试活动都沉淀为可复用的知识。

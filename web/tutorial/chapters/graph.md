# 第 8 章 · 知识图谱：可视化业务流依赖

知识图谱把业务系统的 **业务流依赖** 以力导向图呈现，帮助你直观理解业务域、接口与可测试场景之间的关系，并直接支撑生成时的「按业务模块」范围（黑盒测试不依赖源码，故使用业务流依赖图谱而非代码图谱）。

![知识图谱](/tutorial/assets/graph.png "知识图谱：业务流依赖力导向图")

## 8.1 业务流依赖图谱解读

- 节点 = 一次 API 调用 / 业务步骤（含方法、路径、角色、摘要）；边 = 业务依赖（节点 → 业务域 → 系统根，表示归属与协同）；
- 后台数据驱动自动刷新；上传 PRD / 需求 / API 文档后，点击图谱页右上角「生成业务图谱」即可基于项目 Wiki 重建；
- 悬浮节点可查看其业务域与上下游依赖，理清影响面。

## 8.2 图谱与生成范围的联动

「生成中心 → 测试范围 → 按业务模块」列出的业务域 / 模块，**正来自这张业务流依赖图谱的真实节点**。因此：

- 图谱里有几个业务域，范围里就能选几个；
- 新项目（未生成业务图谱）范围自然为空——这正是第 0 章提到的「不显示 Demo 假模块」改进后的正确行为。

## 8.3 生成业务图谱

知识图谱页右上角提供「⟳ 生成业务图谱」按钮：

- 基于当前项目的 `project-wiki`（PRD / 需求 / API 文档）重建业务流依赖图谱（`POST /api/business-graph`，`ai=true` 走 AI 通道，失败回退确定性骨架）；
- 重建后图谱即时刷新，生成中心的「按业务模块」范围与生成提示词中的业务流上下文同步更新。

## 案例：在图谱中定位某业务步骤的影响面

1. 打开知识图谱，使用力导向布局找到某个业务步骤节点（如登录 / 鉴权相关节点）。
2. 观察其出边（依赖谁）与入边（谁依赖它），判断改动该步骤的影响面。
3. 回到生成中心，测试范围勾选其所属业务域及直接依赖节点，做一次针对性回归生成。
4. 若想聚焦，可在图谱中查看某节点的邻居，再回到生成中心只选这些邻居，避免无关模块干扰。

> 提示：业务流依赖图谱是只读视图，不会因你勾选范围而改变；它反映当前项目 Wiki 解析出的真实业务依赖，黑盒测试无需源码即可使用。

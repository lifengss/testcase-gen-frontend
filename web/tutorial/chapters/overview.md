# 第 0 章 · 概览与快速开始

本章帮助你用最短时间认识 TestGen（知识管理系统 KS 的业务前端），并跑通第一条"生成 → 草稿 → 入库"的知识闭环。

## 0.1 这是什么

TestGen 是一个面向测试 / 研发人员的**知识管理系统（KS）工作台**。它把"写测试用例"这件事沉淀为可复用的知识：

- 你上传代码、PRD、需求列表，系统自动解析出**功能模块**并基于项目 Wiki 构建**业务流依赖图谱**（黑盒测试不依赖源码）；
- 你描述测试诉求，系统基于已有知识**智能生成**测试用例大纲 / 条目 / 自动化脚本；
- 生成结果以**草稿**形式进入审阅，确认后**入库**成为团队共享的质量资产；
- 执行失败、回归报告也能**回流**为缺陷经验与测试报告知识，反哺后续生成。

一句话：**让每一次测试活动都变成可继承、可检索、可复用的知识。**

## 0.2 整体架构

系统采用"前端工作台 → BFF → 知识系统 / AI 平台"的三层结构：

```
┌─────────────────────────────┐
│   TestGen 工作台（本前端）    │   项目空间 / 生成中心 / 草稿 / 入库 / 图谱 / 设置
└──────────────┬──────────────┘
               │  HTTP（BFF 聚合、代理、鉴权、文件转发）
┌──────────────▼──────────────┐
│   BFF（Node / Express :4123）│   业务编排、AI-Adapter、KS-Adapter
└──────┬───────────────┬──────┘
       │               │
┌──────▼──────┐  ┌──────▼──────┐
│  KS 知识系统 │  │  AI 平台     │   用例生成（OpenAI 兼容 / CodeBuddy / 本地模板回退）
│  (:3000)    │  │  (可配置)   │
└─────────────┘  └─────────────┘
```

- **前端工作台**：你所有操作发生的界面（也就是本教程所描述的界面）。
- **BFF**：前后端之间的"业务侧"边界，负责把前端意图翻译成对 KS / AI 平台的调用，并透传文件。
- **KS 知识系统**：知识的存储与检索核心（草稿、Brain 知识库、图谱、审计）。
- **AI 平台**：真正产出用例文本的模型服务，可配置为 OpenAI 兼容接口、CodeBuddy 或关闭（关闭时回退到本地模板）。

## 0.3 五分钟上手

无论做什么，典型流程都遵循下面四步：

1. **建项目**：在「项目空间」新建或选择一个项目，知识按项目隔离。
2. **传材料**：在「生成中心」上传代码 / PRD / 需求，系统据此生成功能模块，并在「知识图谱」页生成业务流依赖图谱；
3. **一键生成**：配置产物类型、测试范围、深度、框架，点击生成，结果进入草稿箱。
4. **审阅入库**：在「草稿审阅」修改后在「入库看板」确认，知识正式沉淀。

## 案例：用默认项目跑通最小闭环

默认已有一个示例项目 `testCaseGenerator`。按以下步骤即可看到一条完整链路：

1. 进入 **生成中心**，确认「测试范围 → 按业务模块」已加载出业务域（若为空，请先在「知识图谱」页点击「生成业务图谱」）；
2. 选择产物类型 **测试用例条目**，范围保持全选，深度选 **冒烟**，框架选 **Pytest**，点击 **生成测试用例**。
3. 生成完成后，结果在生成中心右侧的**流式结果区**展示，并出现「下载 / 保存草稿」按钮。
4. 点击 **保存草稿**，结果以来源 `human_edit` 进入 **草稿审阅** 列表；在草稿中点击某条可查看 / 编辑。
5. 满意后到 **入库看板** 选择该草稿，点击 **确认入库**；成功后该条目进入项目知识库，可在「项目空间」概览指标看到数量增加。

> 提示：首次使用若「测试范围 → 按业务模块」为空，请先上传 PRD/需求，再到「知识图谱」页生成业务流依赖图谱；功能模块由 PRD/需求解析。

# 第 2 章 · 上传材料与知识沉淀

知识系统的价值来自于你喂给它的材料。所有上传都在 **生成中心** 左侧的「文档材料」区完成——这里有三种入口，分别对应不同的知识产物。

![生成中心与文档材料上传区](/tutorial/assets/generator.png "生成中心：左侧为生成配置与文档材料上传卡片")

## 2.1 上传代码 / 接口 → 生成 API 依赖图谱

拖动或点击 **代码 / 接口** 卡片，选择代码压缩包（`.zip/.tar/.gz/.7z`）或单文件（`.py/.js/.ts/.java/.go`）。

- 系统解析源码中的函数调用关系，生成 **API 调用依赖图谱**；
- 图谱节点即「按代码模块」选范围时看到的模块列表；
- **新项目尚未上传代码时，测试范围代码模块为空**，这是正常的（不会像旧版本那样填充 Demo 假模块）。

## 2.2 上传 PRD / 需求列表 → 沉淀项目 Wiki 与功能模块

- **PRD 文档**（`.md/.txt/.pdf`）：沉淀为项目描述 Wiki（`project-wiki`），供生成时作为知识上下文。
- **需求列表**（`.md/.txt/.pdf`）：优先级**高于** PRD，解析后提供「按功能模块」选范围时用到的功能模块树。

上传后点击右上角 **「刷新上下文」**（或 `⟳` 图标），右下角的「知识上下文（只读）」统计（历史用例 / 自动化脚本 / 图谱节点）会实时更新，反映当前项目已积累的知识量。

## 2.3 知识上下文只读采集

生成时所依赖的知识上下文是**只读采集**的，来源包括：

- `D4` 历史缺陷经验（defect-experience）；
- `B3` 业务规则 / 质量规则（quality-rules）；
- `D1/B2/B1` 项目 Wiki、需求、代码图谱等。

系统不会在生成阶段反向改写知识库，保证知识来源的纯净与可追溯。

## 案例：上传一份 PRD，观察知识与范围的生成

1. 在生成中心点击 **PRD 文档** 卡片，选择 `架构设计与技术方案.md`。
2. 等待上传完成（BFF 会做 UTF-8 加固，中文文件名也能正确生成 slug，避免乱码）。
3. 点击 **刷新上下文**，观察「知识上下文（只读）」中图谱节点 / 历史用例数量变化。
4. 切到「测试范围 → 按功能模块」，此时功能模块树会出现该 PRD 解析出的模块，可勾选作为生成范围。
5. 如需 API 依赖，再上传一份代码压缩包，「按代码模块」即会出现真实模块。

> 提示：上传编码建议统一为 UTF-8；若原文件为 GBK，KS 侧 `readTextFile` 已做 GBK 回退与 Latin-1 误读逐层反解兜底。

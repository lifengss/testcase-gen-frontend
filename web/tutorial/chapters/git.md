# 第 9 章 · Git 协同：知识库版本管理

知识库不仅是存储，更是一份**可版本管理的资产**。Git 协同把 Brain 知识目录纳入 Git 管理：远端配置、状态查看、提交、推送 / 拉取、分支与冲突处理，全部在页面内完成。

![Git 配置（S1）](/tutorial/assets/git.png "Git 配置（S1）：远端地址 / 默认分支 / 提交身份；提交/同步/冲突在 S2 后续里程碑")

## 9.1 设计约定

- **身份一致**：前端提供的提交身份（`user.name` / `user.email`）用于 `git commit` 的作者标识，与 KS 侧 Git 协同保持同套约定（无登录验证，仅身份一致）；
- **不存凭证**：KS / BFF 均不存储 Git 密码与 Token，远端鉴权由环境 / 系统凭据完成；
- **真后端优先，Mock 兜底**：BFF 优先转发真 KS 的 `/api/git/*`；KS 不可达或 `GIT_MOCK=1` 时回退契约一致的 Mock 数据（页面会标注「Mock」）。

## 9.2 Git 配置（S1）

「Git 配置」页设置并保存：

- **远端地址（remote）**：如 `https://…/repo.git`；
- **默认分支（branch）**：默认 `main`；
- **提交身份**：用户名 + 邮箱（可选，用于 commit 作者标识）。

保存不触发网络操作；点击 **初始化仓库** 后即可在 Git 状态页看到变更。

## 9.3 Git 状态、提交与同步（S2）

「Git 状态」页提供：

- **状态面板**：当前分支、领先 / 落后提交数、未跟踪 / 已修改 / 已暂存文件分组；
- **提交**：填写提交说明后提交（返回 commit 哈希，若 KS 侧配置了 GBrain 会提示同步状态）；
- **远端同步**：**推送 / 拉取 / 抓取**（push / pull / fetch），成功后显示最新分支与领先落后数；
- **提交历史 / 变更 Diff / 分支管理**：可展开查看最近 50 条提交、文件级 diff，新建 / 切换分支。

## 9.4 冲突处理

推送 / 拉取产生合并冲突时，状态页会显示冲突文件数，并可一键前往「Git 冲突处理」：

- 查看冲突文件内容（冲突标记高亮），选择 **保留本地（ours）/ 保留远端（theirs）/ 保留双方（both）**；
- 或 **手动编辑** 后保存为解析结果；
- 解决后刷新，冲突列表清空，状态页同步更新。

## 案例：配置远端并提交一次变更

1. 打开「Git 配置」，填远端地址、分支 `main`、身份（用户名 + 邮箱），点 **保存配置**，再点 **初始化仓库**。
2. 切到「Git 状态」，看到若干未跟踪文件（知识页面）。
3. 填写提交说明（如 `feat: 沉淀登录模块用例`），点 **提交**，返回 commit 哈希。
4. 点 **推送**，成功后显示与远端一致（领先 0 / 落后 0）。
5. 若团队他人改过同名文件导致冲突，在「Git 冲突处理」按需求选择保留策略或手动编辑解决。

> 提示：`push` 前建议先 `pull` / `fetch` 对齐远端，减少冲突面；冲突解决建议优先「保留双方」或手动合并，避免误丢团队知识。

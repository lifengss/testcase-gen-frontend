# 源摘要：本系统架构设计与技术方案

> 源文件：`raw/03-架构设计与技术方案.md`
> 角色：自动化测试用例生成前端业务系统（TestGen）的权威设计，本 wiki 的编排对象。

## 定位
知识系统的**外部业务前端**：承载用例生成全部用户交互与业务编排。由「前端应用层 + 后端编排层 BFF」组成；不重建 AI harness / 知识存储。

## 六需求落点速记
1. 上传代码 → 生成 projectId → 经 `POST /api/projects` + `POST /api/source-upload` 完成（[[concept:业务端集成模式]]）。
2. 上传 PRD/需求 → 同上传通道，`type` 区分，落入 project-wiki。
3. 多项目 → 复用 `/api/projects` + `currentProject` 注入（[[concept:多项目隔离]]）。
4. 生成大纲/条目/脚本 → 路径A，上下文采集自 D4/B3/D1/B2/B1（[[concept:知识闭环数据流]]）。
5. 回写 → 严格对齐 PRD 双链路双通路（[[concept:知识闭环数据流]]）。
6. UI → 深色科技基底 + 玻璃拟态 + 极光渐变（见 [[entity:测试用例生成前端业务系统]]）。

## 关键模块
- 前端：projects / upload / generator / review / backflow / commit / context。
- BFF：KS-Adapter / AI-Adapter / Intent-Orchestrator / Context-Harvester / Writeback-Orchestrator（[[entity:知识系统API契约]]）。

## 里程碑
M0 脚手架 → M1 多项目+上传 → M2 生成中心 → M3 审阅与回写 → M4 闭环可视化 → M5 打磨。详见同目录 `需求列表.md` 与 `开发计划.md`。

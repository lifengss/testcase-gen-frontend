# 源摘要：AI测试用例自动生成系统-知识闭环能力PRD

> 源文件：`raw/02-AI测试用例自动生成系统-知识闭环能力PRD.md`
> 角色：定义测试用例生成→人工优化→自动执行回流→知识落库→赋能再生成的完整闭环，是本系统需求 5 的回写逻辑来源。

## 闭环总览
AI 生成测试用例 → 人工编辑优化 + 自动化执行回流 → 作为增量知识进入缓冲 → 经冲突检测与质量门控后写库 → 全量知识库更新赋能后续生成。

## 两条增量知识产出链路
1. **人工编辑优化链路**：编辑 AI 生成用例产生有效改动、保存 → 与原始产物 diff → 入库为改进规则（quality_rule / test_case / test_script）。
2. **自动化执行回流链路**：自动化测试执行失败 / 存在错误断言 / 边界遗漏 → 结构化缺陷经验入库（defect_rule）。

## 知识落地双通路
- **批量确认（主）**：冲突检测 → 质量门控 → 批量写入 D1~D4 → 缓存清空 → B3 增量刷新。
- **单条确认（兜底）**：单条冲突检测 → 单条写入 D1~D4 → 清对应缓存 → B3 增量刷新。

## 范围界定（无知识变更不写库）
- 无编辑直接单条确认、编辑取消、批量删除、批量导出、**仅确认状态不入库** → 均为前端交互，不调写接口。
- API 依赖图谱 B3 由后台数据驱动自动刷新，无人工编辑入口。

## 本系统采纳与强化（优化建议）
1. 缺陷草稿结构化：增加 `failure_type` / `missing_assertion` / `boundary` 字段，便于后续检索。
2. 执行回流支持 JUnit/pytest XML 与 JSON 摘要两种格式解析。
3. 单条入库提供「仅确认用例状态 / 同步提交规则」显式选项，避免误写库（见 [[concept:知识闭环数据流]]）。

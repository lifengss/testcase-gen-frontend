# 源摘要：知识管理系统-总体架构设计

> 源文件：`raw/01-知识管理系统-总体架构设计.md`
> 角色：定义知识系统四层架构与「业务端」在其中的位置，是本系统设计的约束来源。

## 关键结论

### 1. 四层架构（GBrain 内核 + 三层增强）
- **L3 GBrain 内核**：Brain 仓库（质量规则 D1 / 缺陷经验 D2 / 项目 Wiki D3 / 历史测试用例 D4），确定性 4 目录结构。
- **L2 缓冲层**：SQLite（C 草稿缓冲、B 持久化索引、D 路由表、A 内存元数据、M 溯源、H 血缘、conflict 冲突、quality 质量门控、audit 审计）+ `draft_cache.py` 增量更新。
- **L1 三层检索**：B1 RRF 融合检索、B2 LM Wiki 项目知识、B3 API 依赖图谱（函数调用关系，后台数据驱动自动刷新）。
- **L0 接入层**：MCP 标准化协议 + RESTful API（端口 3000）+ 业务页面（Web UI 仅管理，日常消费在外部业务系统）。

### 2. 对业务端的明确要求
- 业务页面提交「业务意图」= 操作类型 + 参数（按钮类确定性操作），**不提交完整 prompt**。
- 两条链路：① 确定性生成→业务意图→AI 平台（挑执行模板）→MCP 知识系统；② 源上传/用户确认→REST 直连知识系统。
- **三层 prompt 分离**：业务意图（业务）/ 执行模板（AI 平台）/ 知识上下文（知识系统）；换 AI 平台零改动。
- 不重建 AI harness、不重建知识存储；Web UI 只管理，业务系统承载日常。

### 3. V1.0 里程碑
单人本地、多项目（私有 `brains/<id>/` + 可选 `sharedBrain`）、API 依赖图谱、4 大知识库完整业务流。

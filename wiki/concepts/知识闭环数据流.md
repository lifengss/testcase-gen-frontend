# 概念：知识闭环数据流

> 来源：[[source-summary:AI测试用例自动生成系统-知识闭环能力PRD]] · [[source-summary:架构设计与技术方案]]
> 关联：[[concept:业务端集成模式]] · [[concept:三层Prompt分离]] · [[entity:测试用例生成前端业务系统]]

## 定义
用例生成不是一次性的，而是「生成 → 优化/回流 → 落库 → 赋能再生成」的闭环。知识在闭环中被持续沉淀并反哺下一轮生成。

## 端到端流程
```
AI 生成产物(纯读)
  ├─ 无编辑确认 ─────────────▶ 无知识读写
  ├─ 编辑保存(有改动) ──▶ POST /api/drafts (source=human_edit)
  └─ 上传执行报告 ──────▶ 解析失败 → POST /api/drafts (source=exec_backflow)
                              │
                      (知识系统缓冲层 C)
                              │
        批量确认: conflicts/detect → batch-commit
        单条确认: drafts/:id/commit
                              │
              冲突检测 + 质量门控 + 写 D1~D4 + 清缓存 + 刷新 B3
                              │
              知识回流 B1/B2 ──▶ 赋能下一轮生成（路径 A 上下文采集）
```

## 两条增量知识产出链路
1. **人工编辑优化**：编辑产生有效改动 → diff 原始产物 → 草稿(source=human_edit, type=quality_rule/test_case/test_script)。
2. **自动执行回流**：测试失败/错误断言/边界遗漏 → 结构化缺陷草稿(source=exec_backflow, type=defect_rule)。

## 双通路入库（知识落地唯一入口）
- **批量确认（主）**：冲突检测 → 质量门控 → 批量写 D1~D4 → 清缓存 → B3 增量刷新。
- **单条确认（兜底）**：单条冲突检测 → 单条写 D1~D4 → 清对应缓存 → B3 增量刷新。

## 范围界定（无知识变更不写库）
无编辑直接确认、编辑取消、批量删除、批量导出、仅确认状态不入库 —— 均前端交互，不调写接口。B3 图谱由后台数据驱动自动刷新，无人工编辑入口。

## 本系统强化项
- 缺陷草稿结构化：`failure_type` / `missing_assertion` / `boundary`。
- 回流支持 JUnit/pytest XML 与 JSON 摘要。
- 单条入库显式选项：仅确认状态 / 同步提交规则。

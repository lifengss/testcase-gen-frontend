# 测试用例生成前端（TCGF）V2.0 技术方案

> 版本：V2.0（规划基线：test-knowledge-system/docs/知识管理系统-V2.0-规划.md）
> 配套文档：KS V2.0 技术方案（test-knowledge-system/docs/知识管理系统-V2.0-技术方案.md）
> 定位：本文档定义 TCGF（业务侧前端 + BFF）在 V2.0 的模块拆分、接口契约与对接方案。TCGF 不重建 AI harness / 知识存储，仅编排业务交互并复用 KS `/api/*`。

## 0. 现状基线（V1.0 已定版 v1.0.0）

| 能力 | V1.0 现状 | 来源 |
|------|-----------|------|
| BFF 代理 | `server/index.js` 通配 `app.all('/api/*')` 透传 KS，并单独声明 `/api/generate`、`/api/source-upload`、`/api/projects` 等 | server/index.js:93–821 |
| 路径 A（生成） | `/api/generate` → KS `/api/generate-cases`（AI 平台生成） | server/index.js:374 |
| 路径 B（回流） | `source-upload` 经 `memUpload` + `ksCall('POST','/api/source-upload')` 直连 KS | server/index.js:115–137 |
| 多项目隔离 | BFF 统一默认 project，注入 `/api/projects` 与所有代理 | server/index.js:24 |
| AI 通道 | `server/codebuddy-client.js` 支持 codebuddy/openai/custom 模型（Windows 用 node 直跑入口脚本，免 cmd.exe） | codebuddy-client.js |
| 回测视图 | 前端 `retest` 视图**当前仅读取** `defect-experience`（只读，无分流/重测编排） | web/app.v2.js |
| 后台日志 | `server/logger.js` 统一 JSON 行日志（7 天/LLM 1 天） | logger.js |
| 版本化教程 | `web/tutorial/`（manifest + chapters + assets） | tutorial/manifest.json |

**关键缺口（V2.0 必须解决）**：
1. **无 Git 操作 UI**：前端无 git 配置/状态/冲突页，BFF 未代理 `/api/git/*`（通配代理会自动透传，但前端无调用）。
2. 回测**仅只读展示**，未接「回测分流」规划（历史失败用例优先重测）。
3. 业务图谱、知识库浏览依赖 KS，V2.0 检索增强（hybrid/semantic）需前端增加检索模式切换。
4. 内网友商「模型切换」前端已有 `/api/settings/test` 探测，但需与 KS 自定义模型机制对齐文档。

                │ BFF :4123

## 2. Git 协同 UI（V2.0 核心新增）

### 2.1 对接方式
KS V2.0 新增 `/api/git/*`（见 KS 技术方案 §2.3）。TCGF BFF 已通配代理 `/api/*`，**无需新增路由**，仅需前端调用。若需加审计/限流，可在 BFF 单独声明 `/api/git/*` 前置校验 project。

### 2.2 前端三页（补齐规划缺口）
在 `web/index.html` 导航新增（对齐 KS 三页）：
- **Git 配置页**（data-view=git-config）：调 `GET/PUT /api/git/config`、初始化、远程 URL 测试。
- **Git 状态页**（data-view=git-status）：`GET /api/git/status` + `GET /api/git/log`，按钮触发 commit/pull/push。
- **Git 冲突页**（data-view=git-conflicts）：`GET /api/git/conflicts` + `GET /api/git/diff?file=` 对比展示，选择保留版本。

`web/app.v2.js` 新增 `loadGitConfig/renderGitStatus/loadGitConflicts` 等，复用 `apiGet/apiPost` 注入 `currentProject`（localStorage `kb_currentProject`）。

### 2.3 状态联动
- 顶部 `#project-select` 切换时，Git 三页随 project 重置（与既有 `onProjectChange` 一致）。
- Git 操作失败（如 push 凭证缺失）前端提示「已本地提交，待配置远程」，不阻塞业务。

## 3. 回测分流（V2.0 改造，从只读到编排）

### 3.1 现状
`retest` 视图当前仅 `GET /api/brain/pages?category=defect-experience` 列出历史失败用例，**无优先级/无重测动作**。

### 3.2 V2.0 方案
对接 KS 新增 `POST /api/retest/plan`（KS 技术方案 §6）：
```js
// BFF 代理（或经通配）
const plan = await ksCall('POST', '/api/retest/plan', {
  body: { project, scope, weights: { recentFail: 0.6, severity: 0.4 } }
});
```
前端回测视图改造：
1. **分流列表**：按 KS 返回的优先级（recentFail/severity 加权）排序展示，历史失败用例置顶。
2. **重测动作**：对选中用例调路径 A `/api/generate`（带 `mode=retest` 标记）重新生成，结果经路径 B 回流写 `defect-experience`。
3. **进度/对比**：展示本次重测 vs 历史结果差异（命中率变化）。

> 回测结果回流复用既有 `exec_backflow` 通路（路径 B），逻辑不变。

## 4. 检索增强前端适配（V2.0）

### 4.1 检索模式切换
KS V2.0 `/api/search` 支持 `mode: keyword|semantic|hybrid`。前端搜索框增加模式选择：
- 默认 `keyword`（保兼容）；可选 `hybrid`（向量+BM25+RRF）。
- 调 `POST /api/search`（BFF 已代理），body 透传 `mode/limit/project/rerank`。

> **离线语义检索（V2.0 自带 BGE）**：KS 侧 `retrieval/embedding_service.py` 本地加载安装包内置的 `bge-small-zh-v1.5`（fastembed/ONNX），GBrain 经 `embedding` 段配置实现混合搜索。TCGF 无需部署模型，仅消费 KS 的 hybrid 结果；无外网时语义检索仍可用（与 V1.0 仅关键字相比是 V2.0 关键增强）。详见 KS 技术方案 §4.5。

### 4.2 结果展示
- hybrid 结果项含 `score/source`，前端标注「语义命中」徽标，便于用户判断召回质量。
- 检索为空时回退 keyword（与 KS rerank 失败回退一致）。
- 前端可显示「检索后端：本地 BGE（离线）」状态指示，让用户确认语义召回已生效。

## 5. 内网友商模型切换（前端适配）

### 5.1 现状
- BFF `codebuddy-client.js` 已支持自定义模型（`models.json` + project/local setting-sources 直连，免 CLI 登录）。
- 前端 `/api/settings/test` 已探测 KS 连通性，作为连通状态单一数据源。

### 5.2 V2.0 增强
- 前端「系统设置」页暴露「AI 平台对接」段（ai.provider/endpoint/apiKey/model），与 KS `ai/ai_config.py` 字段对齐。
- 模型切换时前端提示「切换后将经自定义端点直连，无需登录」，并触发 `/api/settings/test` 重探测。
- 离线模式（`ai.provider=none`）前端展示「离线：使用本地模板生成」降级提示。

## 6. 接口契约对照（V2.0 新增/扩展）

| 端点 | 方法 | TCGF 用途 | 来源 |
|------|------|-----------|------|
| `/api/git/config` | GET/PUT | Git 配置页 | KS 新增（通配代理） |
| `/api/git/init` | POST | 初始化仓库 | KS 新增 |
| `/api/git/commit` | POST | 提交变更 | KS 新增 |
| `/api/git/pull` | POST | 拉取远程 | KS 新增 |
| `/api/git/push` | POST | 推送 | KS 新增 |
| `/api/git/status` | GET | 状态页 | KS 新增 |
| `/api/git/log` | GET | 历史页 | KS 新增 |
| `/api/git/conflicts` | GET | 冲突页 | KS 新增 |
| `/api/git/diff` | GET | 冲突对比 | KS 新增 |
| `/api/search` | POST | 检索（mode 扩展） | KS 扩展 |
| `/api/retest/plan` | POST | 回测分流 | KS 新增 |

> 所有列表接口响应为 `{success, data:{items, total}}` 信封；分页用 `pageSize`（默认 20），不认 `limit`。前端须与 `web/src/api-docs-data.js`（KS 单一数据源）保持一致，变更须过 `script-check-skill`。

## 8. 风险与约束

1. **BFF 通配代理顺序**：`/api/git/*` 若要在 BFF 加前置校验，须放在通配 `app.all('/api/*')` **之前**，否则被通配抢占（既有 E2E 教训）。
2. **契约一致**：KS 新增/扩展端点须同步 `web/src/api-docs-data.js`（KS 侧单一数据源），TCGF 仅消费，不另立契约。
3. **不越界**：TCGF 不实现 git/检索后端逻辑，全部委托 KS（用户规则：TCGF 为业务侧，不重建知识存储）。
4. **教程版本**：系统升到 2.x 时 `web/tutorial/manifest.json` 的 `systemVersion` 跟随、`version` 大版本跟随并 `minor` 重置。
